# 四周学习路线

每次学习 30–45 分钟，每周四次。以能完成任务并解释证据为标准，而不是背诵命令参数。

## 第 1 周：Linux 基础

- 识别发行版、用户与组、文件系统布局和挂载点。
- 解释文件与目录权限的区别，并在 [Linux 实验](../labs/linux-basics.md)中验证。
- 理解 CPU、可用内存、负载、磁盘字节与 inode 指标。
- 查找服务状态和限定范围的近期日志。

**验收：** 分别从 inode 与权限两个假设解释“有磁盘空间但无法新建文件”，并说明如何用观测区分。

## 第 2 周：网络与支持实践

- 沿 DNS、路由、TCP 端口、TLS 到应用响应追踪请求。
- 解释为什么 Ping 成功不代表网站或数据库可用。
- 比较失败与正常场景，每次只改变一个条件。
- 编写包含影响、时间线、证据、假设与下一步的工单。

**验收：** 使用[网络指南](../docs/linux/networking.md)诊断模拟连接失败，并完成[交接记录](../templates/incident.md)。

## 第 3 周：MySQL 与 SQL 基础

- 识别服务器、连接方式、认证账户与数据库。
- 在 [MySQL 实验](../labs/mysql-basics.md)中练习 SELECT、WHERE、ORDER BY、LIMIT、GROUP BY 和 JOIN。
- 解释事务提交、回滚，以及未结束事务为何会阻塞其他会话。
- 阅读普通 EXPLAIN，理解筛选条件与索引的关系。

**验收：** 按优先级统计待处理工单、连接工单与负责人，并用两个会话解释锁等待。

## 第 4 周：数据库运维实践

- 收集少量健康信息，区分累计计数与当前负载。
- 区分身份验证、连接容量、行锁与元数据锁。
- 在可丢弃数据库中完成[备份与恢复演练](../docs/mysql/backup-and-restore.md)。
- 编写一份原创排查流程，包含症状、证据、解释、下一步与验证方法。

**验收：** 演示成功恢复，说明 RPO/RTO 限制；为慢查询事件提供简洁的升级处理材料。

## 保持学习记录

每次练习记录：预测、命令或查询、观察结果、解释与下一项检查。真实工作证据应私下保存。每周挑一个练习，不先看答案再重做。

## 自测问题

1. 平均负载与 CPU 利用率有什么不同？
2. `df` 和 `du` 为什么可能不一致？
3. 什么会使 `getent` 与 `dig` 结果不同？
4. TCP 连接被接受能证明什么？还有什么没有验证？
5. MySQL 的 `USER()` 与 `CURRENT_USER()` 有何不同？
6. 为什么睡眠中的 MySQL 会话仍可能影响其他请求？
7. 为什么累计语句总耗时不足以诊断某一分钟的慢查询？
8. 将导出视为可用备份前必须验证什么？

结合指南解释答案，并为每个问题设计一个小测试。
